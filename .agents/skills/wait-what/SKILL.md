# Wait what

Stop. The last message assumed context the owner does not have. Re-pitch it before doing anything else.

## Procedure

1. **Identify the missing context.** Name the assumption the last message made: a term, a prior decision, a system component, a step, or a result the owner has not seen. Why: a re-pitch that repeats the same assumption fails again.
2. **Read the repo glossary.** Read `GLOSSARY.md` at the repo root. If `GLOSSARY-MAP.md` exists, follow it to the `GLOSSARY.md` for the context in play. Use its terms exactly. Why: the owner knows the project's words, and the glossary is where those words are defined.
3. **Re-pitch in plain English.** Start from the missing context. State the point in short sentences, one idea per sentence, in the active voice. Define any term that is not in the glossary. Do not add new findings, options, or work. Why: the owner asked for the same message in words they can follow, not for a new answer.
4. **Stop.** End after the re-pitch and wait for the owner. Do not continue the original task, ask a new question, or add a plan. Why: the owner asked for the last message again, not for the next step.

When the owner challenges a finding, a recommendation, or a fact, load `pushback` before you reply.
